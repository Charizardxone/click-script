# Windows 图像识别点击脚本——需求说明

## 1. 文档信息

- 项目暂定名：Click Script
- 目标平台：Windows 10 / Windows 11
- 开发语言：Python
- 项目与依赖管理：uv
- 当前阶段：需求确认
- 文档版本：0.1

## 2. 项目目标

开发一个带桌面 UI 的 Windows 自动点击工具。用户可以导入或截取目标按钮图片，将多个按钮编排成有顺序的操作步骤，然后由程序在屏幕中识别这些目标并依次执行鼠标点击。

鼠标操作需要具备平滑、非完全直线的移动轨迹，在目标内部选择合理点击位置，到达目标后短暂停留，再完成按下和释放。

本工具定位为用户有权操作的软件自动化和桌面交互测试工具，不以绕过平台风控、验证码、反作弊或其他安全机制为目标。

## 3. 目标用户

- 希望自动执行重复桌面操作的个人用户
- 需要验证桌面 UI 操作流程的测试人员
- 需要制作固定步骤演示或辅助操作流程的用户

用户无需编写 Python 代码即可创建、编辑、保存和运行点击任务。

## 4. MVP 功能范围

### 4.1 目标图片管理

用户可以：

- 从本地导入 PNG、JPG、JPEG 或 BMP 图片
- 通过截图选区创建目标图片
- 为目标图片设置易于辨认的名称
- 查看目标图片缩略图、原始尺寸和文件路径
- 替换或删除目标图片
- 在当前屏幕中测试识别目标
- 查看测试识别的匹配位置和置信度

同一目标允许在脚本中被多次引用。

### 4.2 点击步骤编排

主界面提供步骤列表。每个步骤至少包含：

- 步骤序号
- 目标图片
- 步骤名称
- 图片匹配阈值
- 查找超时时间
- 点击前等待时间
- 点击后等待时间
- 失败处理方式
- 是否启用

用户可以：

- 添加、复制、编辑、删除步骤
- 通过拖拽或上移、下移调整执行顺序
- 临时禁用某个步骤
- 单独测试某个步骤
- 从指定步骤开始执行

### 4.3 脚本运行控制

运行区域至少提供：

- 开始
- 暂停
- 继续
- 停止
- 当前运行状态
- 当前步骤和总步骤数
- 本轮运行次数
- 最近一条执行信息

任务支持：

- 按顺序执行已启用步骤
- 设置整体循环次数
- 设置无限循环
- 设置每轮之间的最小、最大随机等待
- 每个步骤独立设置超时和等待
- 执行期间响应紧急停止操作

暂停后不开始新的鼠标动作；如果鼠标正在移动，程序应在安全检查点尽快进入暂停状态。

### 4.4 图像识别

程序在指定搜索范围内寻找目标图片。MVP 支持：

- 全屏搜索
- 指定显示器搜索
- 自定义矩形区域搜索

识别结果至少包含：

- 是否找到目标
- 匹配置信度
- 目标矩形位置
- 最终点击坐标
- 识别耗时

当存在多个相似目标时，MVP 默认选择置信度最高的目标。后续版本可增加“距离上次位置最近”“最靠近指定方向”等选择策略。

### 4.5 自然鼠标操作

鼠标操作应满足：

- 从当前位置平滑移动到目标位置
- 轨迹使用平滑曲线，不是瞬间跳转或严格直线
- 移动时长参考移动距离，并限制合理的最短和最长时间
- 点击位置在目标内部按二维正态分布采样
- 采样位置限制在目标安全区域内，避免点击边缘
- 到达目标后短暂停留
- 鼠标按下与释放之间保留短暂间隔

自然点击参数允许在“设置”中调整，并提供“保守”“自然”“快速”预设。参数随机化用于改善交互观感和测试覆盖，不保证也不用于绕过第三方反自动化检测。

### 4.6 任务保存与加载

用户可以：

- 新建任务
- 保存任务
- 另存任务
- 打开已有任务
- 查看最近打开的任务

任务文件保存：

- 步骤顺序和参数
- 目标图片引用
- 搜索区域
- 循环配置
- 自然点击配置
- 应用版本和任务格式版本

任务推荐保存为一个独立项目目录，避免移动单个配置文件后丢失目标图片。

### 4.7 日志与调试

程序需要记录：

- 任务开始、暂停、继续和停止
- 每一步开始和结束时间
- 匹配置信度和目标坐标
- 点击坐标
- 超时、异常和重试
- 本次任务最终结果

调试模式可以保存识别失败时的截图，但默认关闭，以减少磁盘占用及避免保存屏幕上的敏感信息。

## 5. UI 页面与交互

### 5.1 主界面布局

建议使用三栏布局：

1. 左侧：目标图片库
2. 中间：步骤编排列表
3. 右侧：当前步骤属性和运行参数

底部固定显示运行控制条、进度和日志摘要。

### 5.2 截图选取流程

1. 用户点击“截图选取”
2. 主窗口临时隐藏
3. 程序截取虚拟桌面并显示遮罩
4. 用户拖动矩形框选择目标
5. 用户确认或重新选择
6. 程序展示预览并要求填写名称
7. 图片保存到当前任务的资源目录
8. 主窗口恢复

按 `Esc` 取消截图，不创建目标。

### 5.3 导入图片流程

1. 用户点击“导入图片”
2. 选择一个或多个图片文件
3. 程序复制图片到任务资源目录
4. 用户确认名称
5. 图片出现在目标库中

### 5.4 创建步骤流程

用户可以把目标图片拖入步骤列表，也可以先点击“添加步骤”再选择目标。新步骤使用默认识别和点击参数，随后可以在属性区调整。

### 5.5 运行前检查

点击开始后，程序检查：

- 至少存在一个已启用步骤
- 所有已启用步骤引用的图片存在且可读取
- 参数范围有效
- 搜索区域与当前显示器布局有效
- 没有另一个任务正在运行

检查失败时不移动鼠标，并在 UI 中显示明确原因。

## 6. 步骤状态与失败处理

单个步骤具有以下状态：

- 等待
- 正在识别
- 正在移动
- 正在点击
- 正在等待点击结果
- 成功
- 失败
- 已跳过
- 已取消

MVP 支持三种失败策略：

- 停止任务
- 跳过当前步骤并继续
- 按配置次数重试

重试之间应有固定或可配置的等待时间。

## 7. 安全与可控性要求

- 默认启用全局紧急停止热键
- 默认支持将鼠标快速移动到虚拟桌面指定安全角触发停止
- 启动任务前显示短倒计时，让用户有机会取消
- 运行期间不得阻塞 UI 主线程
- 停止后不得继续产生新点击
- 所有循环必须可被取消
- 单步骤、单轮和完整任务均应有最大执行边界
- 点击坐标必须位于目标矩形和配置搜索区域内
- 目标过小或安全点击区域无效时禁止点击并报告错误
- 不采集或上传截图、任务文件和日志

## 8. 非功能性要求

### 8.1 易用性

- 常用操作应能通过 UI 完成
- 危险操作和删除操作需要明确提示
- 参数应提供合理默认值和说明
- 运行状态必须清晰可见

### 8.2 性能

- 常规 1080p 屏幕、限定搜索区域时，单次模板识别目标耗时建议低于 500 ms
- 执行期间 UI 保持响应
- 不运行任务时不持续高频截图
- 截图和图像矩阵使用后及时释放

### 8.3 稳定性

- 单个目标识别失败不能导致应用崩溃
- 任务文件损坏时给出可理解的错误
- 日志写入失败不应阻塞紧急停止
- 进程退出前应终止工作线程并释放全局钩子

### 8.4 隐私

- 所有任务和图片默认仅保存在本机
- 不包含联网、遥测和自动上传功能
- 调试截图需要用户主动启用

## 9. MVP 不包含的功能

- OCR 文字点击
- Windows UI Automation 控件定位
- AI 目标检测模型
- 跨设备同步
- 云端任务库
- 远程控制
- 浏览器 DOM 自动化
- 验证码识别
- 绕过反作弊或反自动化检测
- 条件分支、变量、表达式和完整脚本语言
- 录制键盘输入

这些功能可在 MVP 稳定后按需求评估。

## 10. 验收标准

满足以下条件可视为 MVP 完成：

1. 用户可以导入图片或截图创建目标。
2. 用户可以创建至少 20 个点击步骤并调整顺序。
3. 任务保存后重新打开，图片引用、顺序和参数保持一致。
4. 程序能在屏幕或指定区域识别目标并显示置信度。
5. 识别成功后，鼠标沿平滑曲线移动并在目标安全区域完成点击。
6. 连续运行时，每次点击位置存在合理变化，但不会超出目标安全区域。
7. 用户可以暂停、继续和停止任务。
8. 紧急停止能阻止后续点击。
9. 识别超时能按照“停止、跳过或重试”策略处理。
10. 识别、点击和异常信息能在 UI 与日志中查看。
11. 100%、125% 和 150% Windows 缩放下，通过测试用例验证截图坐标与点击坐标一致。
12. 在至少一个双显示器布局中验证搜索和点击坐标正确。

## 11. 待确认事项

以下内容在开始编码前需要确认：

1. MVP 是否必须支持“截图选区”，还是只需要导入已有图片？
2. 是否需要在第一版支持多显示器？
3. 搜索范围是否需要支持绑定到指定窗口？
4. 是否需要无限循环，还是只支持有限次数？
5. 暂停时是否要求立即中断正在进行的鼠标移动？
6. 目标图片是否可能包含透明通道？
7. 是否需要在点击后验证目标消失或另一个目标出现？
