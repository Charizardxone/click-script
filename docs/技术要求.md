# Windows 图像识别点击脚本——技术要求

## 1. 技术目标

使用 Python 构建 Windows 桌面应用，完成目标图片管理、点击步骤编排、屏幕截图、模板识别、自然鼠标移动、任务控制及本地持久化。

技术实现优先考虑：

- 行为安全可停止
- Windows DPI 与多显示器坐标准确
- UI 与执行引擎解耦
- 算法参数可配置、可测试
- MVP 实现简单，后续可以替换截图和识别模块

## 2. 推荐技术栈

### 2.1 基础环境

- Python：3.12
- 包与虚拟环境管理：uv
- 操作系统：Windows 10 22H2 及以上、Windows 11
- 源码编码：UTF-8

项目确认后计划使用：

```powershell
uv init --app
uv venv
uv add pyside6 opencv-python numpy pillow mss pynput
uv add --dev pytest pytest-qt ruff mypy
```

是否生成锁文件：是，提交 `uv.lock`。

### 2.2 UI

推荐使用 PySide6：

- Windows 桌面体验完整
- 支持列表模型、拖拽排序、系统托盘和多线程信号
- 便于实现截图遮罩和图片预览
- LGPL 许可适合大多数桌面应用分发场景，但正式发布前仍需完成许可证核查

UI 必须运行在主线程。截图、识别和任务执行不得阻塞主线程。

### 2.3 截图

MVP 推荐使用 `mss`：

- 获取显示器和虚拟桌面截图
- 性能优于反复调用 PyAutoGUI 截图
- 输出可以方便地转换为 NumPy 数组

截图模块必须以物理像素为统一坐标单位，并显式保存截图区域的虚拟桌面原点。

### 2.4 图像识别

使用 OpenCV：

- `cv2.matchTemplate`
- 默认匹配算法：`TM_CCOEFF_NORMED`
- 图像矩阵：NumPy
- 默认输入：BGR 三通道

MVP 先实现单尺度模板匹配。多尺度匹配作为独立扩展能力保留接口，但不默认开启，以控制执行耗时。

### 2.5 鼠标输入

建议分两阶段：

1. MVP 先通过 PyAutoGUI 或封装层实现鼠标移动和按键。
2. 稳定后将 Windows 输入后端替换为 `ctypes` 调用 Win32 `SendInput`。

业务代码只依赖 `MouseController` 抽象，不直接依赖具体输入库，以便替换实现和进行单元测试。

### 2.6 全局热键

使用 `pynput` 监听全局紧急停止热键。监听器必须：

- 可在应用退出时停止
- 不在回调线程中直接操作 UI
- 只发送线程安全的停止信号
- 回调异常时记录日志

## 4. 架构与线程模型

采用分层架构：

```text
PySide6 UI
    ↓ 命令 / 信号
Application Services
    ↓
Domain Models
    ↓
Capture / Recognition / Mouse / Persistence
```

### 4.1 UI 主线程

负责：

- 窗口和控件
- 用户操作
- 状态展示
- 信号处理

不得执行耗时识别或循环等待。

### 4.2 任务工作线程

负责：

- 执行步骤状态机
- 截图和目标识别
- 鼠标轨迹生成与执行
- 等待和重试

工作线程通过 Qt 信号报告状态，不直接修改 UI 控件。

### 4.3 取消机制

任务执行必须使用线程安全的取消令牌或 `threading.Event`。以下位置必须检查取消状态：

- 开始截图前
- 图像匹配前后
- 鼠标轨迹的每个分段之间
- 到达后的停顿期间
- 鼠标按下之前
- 步骤等待和重试期间
- 进入下一步骤前

如果取消发生在鼠标已经按下之后，必须优先发送鼠标释放，避免鼠标保持按下状态。

## 7. 图像匹配技术要求

### 7.1 基本流程

```text
获取搜索区域截图
  → 转换为 BGR NumPy 图像
  → 校验模板不大于截图
  → matchTemplate
  → minMaxLoc
  → 阈值判断
  → 返回匹配矩形和置信度
```

返回对象：

```python
MatchResult:
    found: bool
    confidence: float
    bounds: Rect | None
    elapsed_ms: float
```

### 7.2 置信度

- 参数范围：`0.0 < threshold <= 1.0`
- UI 默认值建议：`0.88`
- UI 建议范围：`0.70～0.99`
- 低于 `0.80` 时显示误点击风险提示

程序不得仅因为存在最高分结果就点击，必须满足阈值。

### 7.3 坐标转换

匹配结果首先是搜索区域内部坐标：

```text
screen_x = search_region.left + match.left
screen_y = search_region.top + match.top
```

最终点击点必须再次校验：

- 位于匹配矩形内
- 位于搜索区域内
- 位于当前虚拟桌面边界内

### 7.4 DPI

应用应在进程启动早期启用 Per-Monitor DPI Awareness V2。截图、识别和点击统一使用物理像素坐标，避免 Qt 逻辑坐标、Win32 逻辑坐标和截图物理坐标混用。

截图遮罩从 Qt 坐标转换为物理像素时必须有集成测试。

### 7.5 多尺度

MVP 默认要求模板与屏幕目标尺寸大体一致。后续多尺度模式可按以下方式实现：

- 根据目标显示器 DPI 生成少量候选缩放比例
- 缓存缩放后的模板
- 选择所有尺度中的最高置信度结果
- 限制尺度数量，避免线性放大识别耗时

## 8. 自然点击算法要求

### 8.1 点击点的二维正态分布

目标矩形记为：

```text
x, y, width, height
```

先计算安全区域：

```text
safe_left   = x + width  × margin_x
safe_right  = x + width  × (1 - margin_x)
safe_top    = y + height × margin_y
safe_bottom = y + height × (1 - margin_y)
```

点击点以安全区域中心为均值：

```text
X ~ Normal(center_x, width  × sigma_ratio_x)
Y ~ Normal(center_y, height × sigma_ratio_y)
```

采样要求：

- 默认均值为目标中心
- X 和 Y 独立采样
- 使用截断或有限次数拒绝采样
- 结果必须位于安全区域
- 连续采样失败时回退到目标中心
- 宽或高小于最低安全尺寸时拒绝点击

建议初始值：

- `margin_x = 0.20`
- `margin_y = 0.20`
- `sigma_ratio_x = 0.12`
- `sigma_ratio_y = 0.12`

不能简单将超出范围的随机数裁剪到边缘，否则会在安全边界产生异常聚集。应优先使用拒绝采样或真正的截断正态分布。

### 8.2 鼠标轨迹

使用三次贝塞尔曲线：

```text
B(t) = (1-t)³P0
     + 3(1-t)²tP1
     + 3(1-t)t²P2
     + t³P3
```

其中：

- `P0`：当前鼠标位置
- `P3`：采样得到的点击位置
- `P1`、`P2`：根据起终点方向、距离和曲率强度生成的控制点
- `t`：从 0 到 1

控制点要求：

- 轨迹整体平滑
- 曲率与移动距离相关
- 不在每一个轨迹点添加独立随机噪声，避免鼠标颤动
- 轨迹点不得超出虚拟桌面边界
- 很短距离可以使用简化平滑移动

### 8.3 速度曲线

参数 `t` 应经过缓动函数转换。推荐 ease-out cubic：

```text
eased(t) = 1 - (1 - t)³
```

移动时长：

```text
duration = clamp(
    distance / pixels_per_second,
    minimum_duration,
    maximum_duration
)
```

可以对最终时长施加较小范围随机变化，但必须受上下限约束。

### 8.4 到达与点击

完整动作：

```text
生成目标点
  → 生成曲线
  → 分段移动
  → 到达后停顿
  → 再次检查取消状态
  → 鼠标按下
  → 短暂停顿
  → 鼠标释放
```

默认参数建议：

- 到达停顿：60～180 ms
- 按下持续：40～120 ms
- 最短移动：250 ms
- 最长移动：1200 ms

参数范围需要在领域层校验，不能只依赖 UI 输入限制。

### 8.5 等待时间分布与游移

点击前和点击后的等待使用双模式混合分布。设 `u` 为 `[0, 1)` 均匀随机数，`p` 为长等待概率，`k` 为偏向强度：

```text
短等待模式（概率 1-p）：ratio = uᵏ
长等待模式（概率 p）：  ratio = 1-uᵏ
wait = minimum + (maximum-minimum) × ratio
```

默认 `p=0.10`、`k=6.0`，因此大部分等待靠近最小值，少量等待靠近最大值。

等待超过 350 ms 时，可按配置概率执行全屏贝塞尔曲线游移。每次从虚拟桌面安全区域内选择随机目的地，并在基础速度上下按配置比例随机生成本次速度；若剩余等待预算不足以到达目的地，则沿该方向移动到预算允许的位置。

游移只移动鼠标，不产生按键，游移耗时计入原等待时间。点击前发生游移后必须重新识别目标，再从当前位置沿平滑轨迹移动到最新目标坐标，不得直接使用等待前的旧坐标。

### 8.6 可测试性

随机数生成器必须可注入种子，以便：

- 单元测试可复现
- 调试特定轨迹
- 验证所有采样点均在安全区域内

生产运行默认使用系统随机种子，不在任务文件中持久化随机状态。

## 9. 步骤执行状态机

```text
IDLE
  → SEARCHING
  → TARGET_FOUND
  → MOVING
  → ARRIVAL_PAUSE
  → MOUSE_DOWN
  → MOUSE_UP
  → POST_DELAY
  → SUCCEEDED
```

异常分支：

```text
SEARCHING → TIMED_OUT → RETRY | SKIPPED | FAILED
任意可取消状态 → CANCELLING → CANCELLED
```

鼠标按下后发生异常：

```text
MOUSE_DOWN → RELEASE_MOUSE → FAILED/CANCELLED
```

## 10. UI 技术要求

### 10.1 列表模型

目标库和步骤列表使用 Qt Model/View，不将全部数据逻辑写在窗口类中。

步骤拖拽排序后：

- 更新领域模型顺序
- 标记任务为未保存
- 重新计算显示序号
- 不改变步骤 UUID

### 10.2 截图遮罩

截图遮罩覆盖完整虚拟桌面：

- 支持负坐标显示器
- 显示当前选区尺寸
- `Esc` 取消
- 鼠标释放后显示确认与重选操作
- 最小选区尺寸需要限制
- 保存图片前转换为物理像素选区

### 10.3 运行时编辑限制

任务运行时：

- 禁止修改步骤顺序和目标引用
- 允许查看属性
- 允许暂停、继续和停止
- 停止后恢复编辑能力

## 11. 日志要求

使用 Python 标准 `logging`，必要时再引入结构化日志库。

日志分级：

- INFO：任务生命周期和步骤结果
- WARNING：低置信度设置、重试、可恢复问题
- ERROR：识别、输入、文件和线程异常
- DEBUG：候选位置、耗时、轨迹参数摘要

禁止记录：

- 完整屏幕内容
- 用户输入的密码或敏感文本
- 不必要的绝对个人目录信息

日志按大小或日期轮转，并限制保留数量。

## 12. 测试要求

### 12.1 单元测试

至少覆盖：

- 正态分布采样点始终位于安全区域
- 极小目标拒绝点击
- 贝塞尔轨迹起点和终点准确
- 轨迹所有点位于虚拟桌面边界
- 移动时长上下限
- 取消令牌在各阶段生效
- 任务 JSON 序列化和反序列化
- 无效参数校验
- 失败策略状态转换

### 12.2 图像识别测试

使用固定图片夹具覆盖：

- 完全匹配
- 不存在目标
- 多个相同目标
- 模板大于截图
- 阈值边界
- 有轻微颜色差异

### 12.3 集成测试

建立一个本地测试窗口，展示若干已知按钮。自动验证：

- 截图坐标
- 匹配矩形
- 点击坐标
- 100%、125%、150% DPI
- 双显示器和负坐标布局

自动测试默认使用假的鼠标后端，避免测试过程中真实点击用户桌面。真实输入测试必须显式启用。

### 12.4 UI 测试

使用 `pytest-qt` 覆盖：

- 创建和删除目标
- 添加步骤
- 拖拽排序
- 保存和加载
- 运行状态按钮切换
- 验证错误提示
