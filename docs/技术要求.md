# 技术设计与开发检查

Click Script 使用 Python 3.12 与 PySide6 构建桌面界面，使用 mss 截图、OpenCV 模板匹配和 Win32 鼠标输入。依赖声明位于 [`pyproject.toml`](../pyproject.toml)，由 uv 读取锁文件安装。

## 代码入口

| 模块 | 职责 |
| --- | --- |
| [`app.py`](../src/click_script/app.py) | 创建 Qt 应用和主窗口，启动时请求 Windows DPI 感知。 |
| [`ui/main_window.py`](../src/click_script/ui/main_window.py) 与 [`ui/overlay.py`](../src/click_script/ui/overlay.py) | 编辑任务、测试识别、框选截图，以及展示进度和日志。 |
| [`domain/models.py`](../src/click_script/domain/models.py) | 定义任务、目标、步骤、搜索区域和点击参数，负责校验与 JSON 数据转换。 |
| [`application/runner.py`](../src/click_script/application/runner.py) | 运行倒计时、任务循环、识别轮询、失败处理和运行控制。 |
| [`infrastructure/`](../src/click_script/infrastructure/) | 截图、模板匹配、鼠标控制和任务持久化。 |

## 识别与点击

1. **截图**。mss 捕获整个虚拟桌面或步骤配置的矩形区域。截图对象同时记录像素矩阵与区域在桌面上的原点。
2. **模板匹配**。OpenCV 使用 `TM_CCOEFF_NORMED` 计算匹配分数。默认取最高分位置，并用步骤阈值判断是否命中。模板缓存按文件修改时间更新，匹配坐标加上截图原点后得到桌面坐标。
3. **点击前复核**。首次找到目标后先按配置等待，再取一帧重新识别。复核成功时使用新坐标。复核未达到阈值时，本次尝试结束并按步骤策略处理。复核发生在鼠标开始移动前，移动期间仍可能发生画面变化。
4. **点击轨迹**。在目标矩形向内留出边距，分别对横纵坐标做正态采样，拒绝落在安全区域外的样本。达到采样次数上限时使用中心点。移动采用带三次缓动的贝塞尔曲线，时长按距离、速度和上下限计算。到达后短暂停顿，再使用 Win32 输入发送按下和释放。
5. **等待**。点击前后及轮间等待从指定的时间区间取值。默认有 90% 的概率进入偏向区间下限的短等待模式，其余进入偏向上限的长等待模式。满足条件时可在等待预算内平滑移动鼠标，参数可在「自然点击设置」中调整。

## 线程与失败处理

主窗口创建 `QThread` 并将 `TaskWorker` 移到工作线程。任务通过 Qt 信号报告运行状态、当前轮次、步骤结果和日志。暂停与取消通过线程事件传递，轮询、等待和轨迹移动在检查点响应。若取消发生在鼠标按下后，`finally` 会尝试释放按键。全局停止热键通过 pynput 注册，再由 Qt 信号触发界面的停止处理。

「停止任务」在当前步骤失败时结束任务。「跳过步骤」继续执行下一步。「重试」按配置的间隔和次数再次查找，耗尽后结束任务。只有需要执行下一轮时才进行轮间等待。

## 任务文件

任务由 `task.json` 和 `images/` 组成。`task.json` 保存格式版本、目标图片引用、步骤顺序和参数。保存时复制图片并记录相对路径，配置通过同目录的临时文件替换。加载时解析资源的实际位置，并拒绝指向任务目录之外的图片路径。

## 开发检查

在仓库根目录运行以下命令。

```powershell
uv run ruff check src tests
uv run mypy src
uv run pytest
```

[现有测试](../tests/)覆盖任务校验、配置往返、图片路径边界、模板匹配坐标、点击点采样、轨迹终点、取消时释放鼠标以及轮间等待。真实桌面上的截图选区、高 DPI 坐标、全局热键和 Win32 输入需要在 Windows 环境联调。单次匹配耗时可从「测试识别」读取，受截图范围、图片尺寸和设备影响。
